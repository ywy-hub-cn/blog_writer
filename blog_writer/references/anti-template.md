【反模板化写作模块｜适用于清单类与SEO正文】

一、总原则
1. 文章必须保持清晰、统一、可扫读，但不得出现“外层整齐、内层同构”的模板化写法。
2. 所谓“模板化”，不仅指结构重复，也包括首句句型重复、论证路径重复、语气重复、判断方式重复。
3. 写作目标是“统一框架下的多样展开”，不是“复制粘贴式整齐”。

二、清单类文章的结构规则
1. 对于 listicle / ideas / tips / ways / campaign ideas / best practices 类文章，允许统一一级结构，例如：
- 编号小标题
- 一句核心定义
- 示例或场景
- 执行提醒或衡量建议

2. 但禁止所有条目都使用完全相同的二级展开顺序。
3. 不允许整篇反复循环固定模式，例如：
- 定义 → why it works → example → KPI
- 概念 → 好处 → 模板 → 指标
- 结论 → 解释 → 示例 → CTA

4. 每个条目在正式写作前，必须先判断其类型。常见类型包括：
- 互动型
- 转化型
- 传播型
- 留存型
- 信任建立型
- 收尾型
- 教育型
- 分层/筛选型

5. 不同类型条目必须优先展开不同重点，不得混写成同一套逻辑。
例如：
- 互动型：优先写参与门槛、回复机制、即时反馈
- 转化型：优先写适配品牌、成交条件、行动阻力
- 传播型：优先写转发动力、奖励设计、分享触发点
- 留存型：优先写后续承接、复购逻辑、周期价值
- 信任建立型：优先写可信度边界、避免做作、结果验证
- 收尾型：优先写闭环价值、复盘意义、如何延续关系
- 教育型：优先写信息价值、低压力推进、软转化路径
- 分层/筛选型：优先写标签作用、后续分群、内容承接

三、每个条目的展开重点必须轮换
1. 每个条目只从以下重点中选择 1-2 个作为主展开方向，不要全部都写，也不要所有条目都写同一种重点：
- 为什么有效
- 适合谁
- 不适合谁
- 适用场景
- 执行难点
- 风险提醒
- 常见误区
- 如何衡量
- 如何与前后步骤衔接
- 如何避免显得做作、失真或空泛

2. 连续 3 个条目不得使用相同的二级展开结构。
3. 若上一条重点在“为什么有效”，下一条优先改为“适合谁 / 风险 / 误区 / 执行条件 / 不适合谁”等其他重点。
4. 至少 1/3 的条目必须包含“边界判断”，例如：
- 哪些品牌更适合
- 哪些团队不适合照搬
- 什么情况下会失效
- 哪类表达容易翻车
- 哪类动作看起来有效但实际不值得做

四、句法与段落必须去同构
1. 禁止多个条目连续使用高度相似的首句句型。
2. 避免反复使用以下模板句式：
- This works because...
- This campaign helps brands...
- This approach builds...
- This idea creates...
- This strategy is effective because...
- One reason this works is...
- Another reason this works is...

3. 小节首段必须轮换开头方式，可交替使用：
- 先给结论
- 先给适用场景
- 先给常见误区
- 先给风险提醒
- 先给用户动作
- 先给执行建议
- 先给限制条件

4. 不允许连续多个条目都使用“先定义概念，再解释好处”的机械写法。
5. 句子长度与节奏必须有变化，避免每段都由相似长度、相似句法、相似语气组成。

五、不要只会解释，要做判断
1. 每个条目不能只说明“这是什么”和“为什么有效”，还应尽量体现“何时成立、何时不成立”。
2. 对于每个重要条目，优先加入一种判断信息：
- 适合已经有相关基础的品牌
- 不适合刚起步或缺乏承接页的团队
- 适合高意向用户，不适合冷受众
- 适合节日预热，不适合收尾阶段
- 适合作为参与动作，不适合作为主转化动作

3. 不要把所有条目都写成“看起来都值得做”。应自然体现轻重缓急、适配差异和执行门槛。

六、避免“高完成度模板稿”的典型特征
1. 不要每个条目都平均用力。应有主次，有的讲策略，有的讲风险，有的讲场景。
2. 不要每个条目都配同等长度的解释。根据价值大小分配篇幅。
3. 不要每个条目都同时出现“定义 + 为什么有效 + 示例 + KPI + CTA”。只保留最必要的部分。
4. 不要堆砌看似专业但通用的空泛判断，例如：
- builds engagement
- creates urgency
- drives participation
- boosts authenticity
- strengthens emotional connection
除非后面立刻补充具体原因、适用条件或机制解释。

七、清单类文章的推荐写法
1. 保持外层统一，但让内层重点变化。
2. 可采用以下轮换方式：
- 条目A：结论 + 为什么有效 + 示例
- 条目B：结论 + 适合谁 + 风险提醒
- 条目C：结论 + 常见误区 + 更稳妥的执行方式
- 条目D：结论 + 如何衡量 + 后续承接
- 条目E：结论 + 不适合谁 + 替代方案

3. 同一篇文章里，应至少出现 4 种不同的二级展开组合。
4. 读者读到第 5 个条目时，不应该已经完全预测第 6 个条目的展开方式。

八、写前规划要求
1. 正式写正文前，先在内部完成“条目结构分配”：
- 每个条目的类型
- 每个条目的主展开重点
- 每个条目的首句起手方式
2. 写作时严格按该分配执行，避免相邻条目重复结构。

九、写后自检要求
输出正文前，必须检查以下问题：
1. 是否有超过 40% 的条目使用同一种二级展开模式
2. 是否连续多个条目的首句句法高度相似
3. 是否多个条目都只是在重复“为什么有效”
4. 是否多个条目都缺少“适用边界”或“风险提醒”
5. 是否读到后半段会明显出现流水线感
6. 是否整篇只是“整齐”，但没有真正的判断差异

若存在以上问题，必须先打散结构、补充判断、调整句法后再输出正文。

十、最终目标
目标不是写出“绝对不重复”的文章，而是写出：
- 外层稳定
- 内层有变化
- 每条有判断
- 整体不机械
- 像成熟编辑组织过的清单文
而不是像批量生成的模板清单。

## 十一、非清单类文章（散文/解释型/指南型）的模板化风险

之前的规则主要针对清单类文章。对于解释型/指南型/概念型文章（如 A2P routing 机制解释），规则补充如下：

### 11.1 禁止过度使用定义句作为段首
连续 2 段以上不得以以下句式开头：
- "X is…" / "X refers to…"
- "X describes…" / "X is a process by which…"
- "In the context of X, Y refers to…"
- "X can be defined as…"
- 中文对应："是指…"、"指的是…"、"是指一种…"

必须轮换段首句式：定义句 → 场景句 → 对比句 → 问题句 → 结论句 → 案例句

### 11.2 必须包含差异化框架
文章不应仅按"定义→路径→因素→FAQ"的通用结构排列。正文应加入至少一个以下差异化元素：
- 业务决策框架（发送前检查清单、选型评估表）
- 场景对比透视（不同业务类型下的 routing 差异）
- 常见判断误区（其他文章普遍讲错或忽略的部分）
- 边界条件说明（什么情况下某条规则不成立）

### 11.3 正文必须有明确结论收束
结尾部分（最后 1-2 段）必须满足：
- 不是对前文的简单总结
- 不是机械的"综上所述"
- 必须是核心判断的提炼 + 明确的下一步行动方向
- 让人读完后知道"我认为最关键的是什么"和"接下来应该做什么"

### 11.4 句式多样性要求
每 300 字内不允许出现 3 次以上相同句法骨架，包括但不限于：
- "X is Y"（定义句）
- "X determines Y"（因果句）
- "X plays a key role in Y"（角色句）
- "One of the key factors is…"（列举句）

### 11.5 表格内容必须有具体业务场景
任何对比表格不得仅有通用的维度定义。每个维度行必须有 1-2 个具体业务场景示例，让读者能代入自身情况判断。

### 11.6 引文必须对应正文
每条 References 在正文中必须有对应的 [N] 标注，来源不与正文具体判断对应时，不应出现在 References 列表中。

### 11.7 章节数量与引言数字必须一致

首段/引言中出现的数字枚举（如「5 种策略」、「3 个阶段」、「7 个方法」）必须与正文中实际的 H2/H3 数量严格一致：

#### 规则

1. **首段声明数 = H2 枚举数** — 如果引言说「下面介绍 5 个关键方法」，正文必须有且只有 5 个对应主题的 H2
2. **H2 编号不跨级** — 如果 H2 包含数字编号（如「Strategy 1」），编号必须连续且不跳号
3. **禁止不匹配** — 不允许引言写「5 个方法」但正文只有 3 个 H2，或写了 7 个 H2

| ❌ 错误示例 | ✅ 正确写法 |
|------------|------------|
| 引言：「3 种 SMS campaign 类型」→ 正文 H2 写了 5 种 | 引言：「5 种 SMS campaign 类型」→ 正文 H2 恰好 5 个 |
| 摘要：「7 个 best practices」→ 正文只有 4 个 H2 | 摘要：「4 个核心 best practices」→ 正文 H2 恰好 4 个 |
| 开头：「本文覆盖 5 个 use cases」→ 正文 H3 写了 7 个 | 开头：「本文覆盖 7 个 use cases」→ 正文 H3 恰好 7 个 |

#### 检验方法

在 S004 写完后：
1. 提取引言第一段中的数字（如「5 个」、「3 种」）
2. 统计正文中 `^## ` 开头的 H2 数量
3. 两个数字不一致 → 退回修改（改引言数字或改正文 H2 数，以正文为准）

> 注意：如果引言中没有数字枚举或使用了「几个」「一些」等模糊量词，则本规则不适用。

### 11.8 标题中的编号必须与正文连续

如果 H2 标题使用了编号（如「Strategy 1」、「Reason #2」、「Step 3」），必须满足：
- 编号从 1 开始
- 编号连续，不跳号
- 最后一个编号与 H2 总数一致

例外：如果编号不代表顺序（如「5 个关键指标」中的 5 只是总量），则不受此规则约束。
