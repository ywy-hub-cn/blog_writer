# 引用规则与数字使用规范

> 适用于 S004 正文写作 + S008 自审评分。每个引用都应有与之匹配的强度等级。

---

## 一、需要引用的事实类型（必须标注来源）

以下类型的表述一律需要可核验的外部来源，不得无依据撰写：

| 类型 | 示例 |
|------|------|
| **法规 / 行业规则** | GDPR 罚款金额、CCPA 适用范围、电信行业牌照要求 |
| **平台规则** | Apple 30% 抽成、Twilio 定价、Google 的 SMS 类别划分 |
| **技术概念的定义/原理** | SMPP 协议如何工作、SS7 信令的角色、路由算法的分类 |
| **市场数据** | 市场规模、增长率、占比、渗透率 |
| **用户行为数据** | 打开率、点击率、转化率、留存率、行业基准线 |

**没有可查证来源时：** 不得使用具体数字，改为条件判断或趋势判断。

---

## 二、引用强度等级

每次引用前，先判断该信息属于哪个强度等级，按对应规则处理。

### 低引用强度
- **适用场景：** 内部资料改写、轻量说明、发布包修正、非事实密集型文章
- **处理方式：** 可以引用品牌知识库或经验性描述，不需要外部权威来源佐证
- **格式要求：** 描述性引用，不强制含 URL

### 中引用强度
- **适用场景：** 常规 SEO 正文、行业解释文章、方法论文章
- **处理方式：** 需要至少一个可查证的行业公认来源（行业博客、官方文档、白皮书）
- **格式要求：** `[来源名称](URL) — 该来源提供了XX信息`
- **数量要求：** 至少 2 条引用分布在正文关键位置

### 高引用强度
- **适用场景：** 法规解读、合规说明、平台规则解释、技术判断、行业数据引用、高风险主题
- **处理方式：** 必须使用一手或权威二手来源，交叉验证
- **格式要求：** `[来源名称](URL) — 具体的引用内容说明`
- **额外要求：** 同一数据点尽量提供多个来源，正文需包含"根据某来源，……"的标注

---

## 三、数字使用规则

### 允许使用的数字来源（按优先级）

| 优先级 | 来源类型 | 示例 |
|--------|---------|------|
| P0 | 用户提供的数据 | 客户案例中的实际数据 |
| P0 | 上传资料中的数据 | 品牌资料库中的自有数据 |
| P1 | 可查证权威来源 | 官方文档、Gartner 报告、Statista |
| P2 | 可查证行业来源 | 知名行业博客、技术文章、行业调查 |
| P3 | 同行推算/行业共识 | 需标注"据行业通常认知"等限定词 |

### 当缺少可靠数字时

禁止写伪精确数字。改为以下写法之一：

- **条件判断：** "当规模超过每日XX万条时，通常需要……"
- **场景判断：** "在需要高频发送的场景下，这种方法更适用"
- **趋势判断：** "近年来行业越来越倾向于……"
- **风险判断：** "主要风险在于配置复杂度较高"
- **相对优先级判断：** "相比方案 A，方案 B 在可维护性上更有优势，但这取决于团队技术能力"

---

## 四、表达风险控制

| 维度 | 规则 |
|------|------|
| **具体数字** | 必须使用可查证来源，不得编造 |
| **行业结论** | 必须补充适用条件，"在……场景下成立，在……情况下不适用" |
| **案例分析** | 必须说明案例的成立前提（行业、规模、时间段），不得直接推成普遍规律 |
| **品牌表达** | 保持能力边界，不说"我们是最好的"，改用"我们专注于……"、"我们的优势在于……" |
| **CTA 强度** | 匹配文章所处阶段：信息型文章用弱CTA（"了解更多"），决策型文章用中强CTA（"联系团队评估"） |

---

## 五、正文深度要求

| 维度 | 规则 |
|------|------|
| **核心观点** | 每个核心判断至少补充一个适用条件或不适用情况 |
| **重要建议** | 体现优先级：如果只能做一件事，先做什么；资源有限时优先做什么 |
| **指标/检查项** | 说明判断价值：这个指标高了/低了分别说明什么，值得关注的门槛在哪 |
| **方法说明** | 包含失败条件（什么情况下这个方法会失效）或简化版本（资源不足时怎么做替代方案） |

---

## 六、写后自检清单

输出前必须逐项检查：

1. 正文中是否有任何无来源的具体数字 —— 有则删或改
2. 每条 References 是否标注了可访问的 URL —— 无则补充
3. 行业结论/案例是否补充了适用条件或不成立场景 —— 无则补充
4. CTA 是否与文章阶段匹配 —— 不匹配则调整强度
5. 是否有被写成"最佳"但实际没有依据的绝对化表述 —— 有则降级

## 七、References 禁止使用品牌自有域名

### 7.0 核心规则

**References 中的所有引用来源必须为独立第三方权威来源（行业标准组织、监管机构、技术文档、研究机构、知名行业博客等），不得使用品牌自有域名（如 smsboosting.com）。**

规则细则：

| 允许 | 禁止 |
|------|------|
| GSMA / CTIA / 3GPP 等行业标准组织 | smsboosting.com 或旗下子域名 |
| 国家电信监管机构（FCC, TRAI, Ofcom 等） | 品牌自己的知识库 |
| 知名技术博客（Twilio Blog, Sinch Blog 等） | 品牌产品页面 |
| 学术论文 / 行业白皮书（非品牌出品） | 品牌案例页面 |
| 第三方行业报告（Gartner, Forrester, Statista 等） | 品牌联系/关于页面 |

**品牌自有内容如何处理：**
- 品牌相关页面（如服务介绍、资质说明）→ 只能作为正文内部链接（CTA / 推荐阅读），不能列入 References
- 品牌自有数据 → 在正文中标注

正文中对 References 的使用必须满足以下条件之一：

| 标注方式 | 示例 | 说明 |
|---------|------|------|
| **文内编号** | "...根据 GSMA 的定义[1]，A2P SMS routing 是指..." | 正文中用 [N] 标注对应 References 列表中的第 N 条 |
| **括号标注** | "...行业报告指出，合规路由可降低 40% 的过滤风险（GSMA, 2025）" | 正文中用 (来源, 年份) 标注 |
| **来源前置** | "GSMA 在 SMS White Paper 中指出，..." | 正文中直接写出来源名称 |

**检查要点：**
- 每条 References 在正文中至少出现一次对应的 [N] 或等价标注
- 正文中引用的具体数据/判断/定义必须有标注指向来源
- 不得出现 "References 末尾列了链接但正文完全没对应" 的情况

### 7.2 写入正文时的格式要求

正文中的 [N] 标注插入在引用内容之后：
```
根据 GSMA 的 SMS White Paper[1]，A2P 消息在跨运营商路由时涉及多层合规检查。
```

References 节格式：
```
## References

1. GSMA. SMS White Paper: A2P Messaging and the Role of the Mobile Network Operator. https://www.gsma.com/...
2. CTIA. A2P 10DLC Messaging Guidelines. https://www.ctia.org/...
```

## 八、引用编号与正文数据对应规则

### 8.1 引用编号必须双向对应

正文中每个 `[N]` 标注必须在 `## References` 节中存在对应的条目，反之亦然：

| 规则 | 说明 | 错误示例 |
|------|------|---------|
| **已引用必有来源** | 正文中出现 `[1]`，References 必须有 1. 或 [1] 对应的条目 | 正文有 `[1]` 但 References 没有编号 1 |
| **已列出必被引用** | References 中的每条必须在正文至少出现一次对应的 `[N]` | References 有 5 条但正文只引用了 [1][2] |
| **编号顺序无关** | 不要求引用编号按顺序出现，可以 [3][1][2] | 允许跳号，但不允许空号 |

### 8.2 References 描述必须与正文标注数据对应

每条 Reference 的描述必须明确说明**该来源提供了哪个具体数据或判断**，不能是笼统的行业介绍：

| ❌ 错误写法 | ✅ 正确写法 |
|------------|------------|
| `SMS Marketing Guide — 提供了SMS营销的最佳实践` | `SMS Marketing Guide — 提供了 CTR 5.76% 和 RPR $0.11 的行业基准数据` |
| `Industry Report — 关于短信营销的行业报告` | `Industry Report — 支撑正文中「合规路由降低 40% 过滤风险」的判断` |

> 检验方法：在正文中搜索 `[N]` 并对照 References 中的编号，逐条确认描述与被引用的数据吻合。

### 8.3 正文中的数字 / 标语 / 章节数与文章结构必须一致

正文中出现的以下元素在**数量上必须与文章结构严格一致**：

| 检查项 | 说明 | 错误示例 |
|--------|------|---------|
| **H2 枚举数** | 如果首段说「下面介绍 5 个策略」，正文必须有恰好 5 个对应的 H2 | 首段说「5个策略」但只有 3 个 H2，或写了 7 个 H2 |
| **标题中数字** | H2 中的编号不能与正文章节数冲突 | H2 说「Strategy #4」但正文只有 3 个策略 |
| **标语一致性** | 摘要/引言中的数量词必须与正文实际数量一致 | 「本文涵盖 3 种方法」→ 实际上写了 5 种 |

> 检验方法：统计正文中 `^## ` 开头的 H2 数量，与引言/首段中出现的数字对比，不一致即错误。

## 九、写后自动化验证

以上规则中可通过脚本自动校验的部分：
1. `[N]` ↔ References 双向对应 → `validate_content.py`
2. H2 数量 ≥ 4 → `validate_content.py`
3. 关键词在前 100 词且 ≥ 3 次 → `validate_content.py`
4. References 条数 ≥ 2 → `validate_content.py`
5. References 无笼统概括 → `validate_content.py`
6. References 无品牌域名 → `validate_content.py`

正文写入后必须运行验证脚本，不通过则退回修改。
