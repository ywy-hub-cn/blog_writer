# TraffiClimb 博客视觉规范

**Blog Visual Guidelines · v1.0**

> 基于现有博客 HTML/CSS 反向提炼的执行规范。


## 适用范围

TraffiClimb 英文博客文章页、长篇指南、研究报告、数据型内容与 SEO 教育内容。

## 文档状态

### 使用说明

本文件将提供的单篇 HTML 视作“现有品牌实现样本”，从其中提炼视觉语言、设计变量、页面结构、组件样式、响应式行为和发布检查项。它可以直接作为后续博客制作的执行基线。

> **证据等级**
>
> “明确”表示数值或行为直接来自 CSS/HTML；“推断”表示由元数据、文案结构或单篇样例合理推导，仍建议通过更多历史页面或品牌资产确认。

## 核心判断

- **品牌气质：**专业、克制、数据导向；用深灰建立权威感，用砖红制造识别和行动焦点。

- **视觉语言：**大留白、紧凑标题、舒展正文、圆角信息容器、轻阴影和高对比数据组件。

- **内容策略：**每个章节先给“直接答案”，再给论证、数据、步骤、表格或图示，最后承接 CTA。

- **实现原则：**优先使用 CSS 变量和语义化组件，不在单篇文章中发明新的颜色、圆角或阴影。

## 规范状态

| **类别**                         | **状态** | **说明**                                           |
|----------------------------------|----------|----------------------------------------------------|
| 颜色 / 字体 / 宽度 / 圆角 / 阴影 | 明确     | 直接读取 :root 设计变量与组件 CSS。                |
| 标题层级 / 正文节奏 / 组件结构   | 明确     | 由 HTML 标签、类名与间距规则确认。                 |

| Logo 安全区 / 摄影 / 图标系统    | 未定义   | 当前样例未提供，需要额外品牌资产确认。             |

## 01 品牌视觉原则

TraffiClimb 的博客视觉系统不是“营销型花哨设计”，而是以可信度、清晰度和可引用性为核心的专业内容界面。每个设计决策都应帮助读者更快识别论点、数据、步骤和行动入口。

### 四条设计原则

| **原则**       | **执行含义**                                                               |
|----------------|----------------------------------------------------------------------------|
| 清晰优先       | 层级必须一眼可读；标题、导语、正文、数据、引用和行动区块各有明确视觉角色。 |
| 权威但不沉重   | 深灰与高对比用于建立可信度，浅灰背景和较大圆角用于降低技术内容的阅读压力。 |
| 克制的品牌强调 | 品牌红只用于链接、列表标记、引用边线、参考编号和主 CTA；不要大面积铺红。   |
| 数据可引用     | 表格、统计、流程图和代码必须易扫描、易复制、易截图、易被其他作者引用。     |

### 品牌关键词

| **关键词**   | **视觉表达**                                         |
|--------------|------------------------------------------------------|
| Professional | Inter 字体、深灰正文、结构严谨、少装饰。             |
| Evidence-led | 表格、引用、参考文献、结构化数据和明确数字。         |
| Actionable   | 步骤列表、对比矩阵、工具/模板导向 CTA。              |
| Modern       | clamp 响应式字号、22–28px 大圆角、轻阴影、扁平插画。 |

> **不要做**
>
> 避免霓虹渐变、玻璃拟态、重阴影、过多图标、彩色正文、复杂动效和大量居中排版。这些会削弱“研究型、可执行”的品牌印象。

## 02 色彩系统

色彩系统由一个主品牌红、一个深红交互色、一个辅助亮红、九级中性色和一个页面背景色构成。整体使用比例建议：中性色 85–92%，白色 5–10%，品牌红 3–5%。

### 品牌主色与中性色

| **色样** | **Token**        | **HEX**  | **角色** | **推荐用途**                                 |
|----------|------------------|----------|----------|----------------------------------------------|
|          | **tc-red**       | #B22222 | 主品牌色 | 链接、列表 marker、引用边线、参考编号、CTA   |
|          | **tc-red-dark**  | #7F1D1D | 深红     | CTA hover、行内代码文字、强调态              |
|          | **tc-red-light** | #DC3545 | 亮红     | 封面或小面积辅助强调；当前正文组件中低频     |
|          | **tc-gray-900**  | #18181B | 主墨色   | 正文、标题、表头、代码块、深色 CTA 背景      |
|          | **tc-gray-800**  | #2D2D2D | 次深灰   | H3、lead、深色渐变终点                       |
|          | **tc-gray-700**  | #52525B | 辅助文字 | 引用、FAQ 答案、参考文献、次要标题           |
|          | **tc-gray-500**  | #888888 | 元信息灰 | 作者、日期、bio、reading time                |
|          | **tc-gray-300**  | #CCCCCC | 弱边线   | 参考链接下划线、次级分隔                     |
|          | **tc-gray-200**  | #E8E8E8 | 主边线   | 卡片边框、表格分隔、分区边线                 |
|          | **tc-gray-100**  | #F5F5F5 | 浅底色   | blockquote、行内代码、偶数表格行、Mermaid 底 |
|          | **tc-white**     | #FFFFFF | 纯白     | FAQ 卡片、深色背景反白文字                   |
|          | **tc-bg**        | #F4F4F6 | 页面底色 | body 全局背景                                |

### 色彩使用规则

- **品牌红只承担“可操作/可引用”信号：**链接、CTA、列表标记、引用边线、参考编号。

- **正文不使用彩色大段文字：**正文保持 tc-gray-900，以免降低长文可读性。

- **深色容器内只用白色与浅灰：**标题 white，说明 gray-200，按钮 red。

- **边框优先 gray-200：**gray-300 仅用于更弱的链接下划线或次级分隔。

- **红色不可替代错误色：**该样例未定义状态色；表单错误、成功、警告需另建系统，不要直接借用品牌红。

## 03 字体与文字层级

Web 主字体为 Inter，系统回退为 system-ui / -apple-system / BlinkMacSystemFont / Segoe UI / sans-serif；代码使用 SF Mono / Fira Code / Roboto Mono / monospace。中文扩展建议使用 Noto Sans SC 或思源黑体作为东亚文字回退。

### Web 字号层级

| **层级**   | **字号 / 行高**                       | **字重** | **字距** | **颜色**            | **用途**             |
|------------|---------------------------------------|----------|----------|---------------------|----------------------|
| H1         | clamp(1.72rem, 2.2vw, 2.3rem) / 1.04  | 800      | -0.04em  | gray-900            | 文章唯一主标题       |
| H2         | clamp(1.24rem, 1.8vw, 1.72rem) / 1.04 | 700      | -0.02em  | gray-900            | 主章节标题           |
| H3         | 1.1rem / 1.3                          | 600      | 默认     | gray-800            | 章节内子主题         |
| Lead       | 19px / 1.6                            | 500      | 默认     | gray-800            | 每个 H2 后的直接答案 |
| Body       | clamp(.95rem,1.2vw,1.05rem) / 1.75    | 400      | 默认     | gray-900            | 长篇正文             |
| Meta       | 14px                                  | 400      | 默认     | gray-500/700        | 作者、日期           |
| Pill       | 12px                                  | 400      | 默认     | gray-500            | 阅读时长标签         |
| Table Head | 13px                                  | 600      | 0.5px    | white               | 大写表头             |
| Code       | 14px / 1.6                            | 400      | 默认     | red-dark / gray-100 | 行内/块级代码        |

### 排版节奏

- **标题紧凑、正文舒展：**H1/H2 行高 1.04，正文全局行高 1.75。

- **H2 章节间距：**上 48px、下 16px；首个 H2 不设上边距。

- **H3 间距：**上 28px、下 10px。

- **正文段落：**段后 18px，不使用首行缩进。

- **列表：**外边距 12px 0 24px 24px；项间距 8px。

> **标题写法**
>
> H1 只出现一次；H2 应能独立表达一个搜索意图；每个 H2 后优先放一段 lead 直接回答问题，再进入解释、证据和步骤。

## 04 页面网格与间距

文章采用单栏内容容器，最大宽度 1120px，桌面端上下留白显著，移动端切换为 16px 水平安全边距。视觉节奏来自统一的 8px 倍数间距，而非额外装饰。

### 容器与安全区

| **项目**      | **桌面**       | **移动端 ≤768px** | **说明**                   |
|---------------|----------------|-------------------|----------------------------|
| 最大内容宽度  | 1120px         | 100%              | 容器居中                   |
| 文章顶部      | 48px           | 32px              | 页面进入留白               |
| 文章底部      | 80px           | 60px              | 结尾呼吸空间               |
| 水平内边距    | 由站点壳层提供 | 16px              | 当前 HTML 仅移动端显式设置 |
| Header 到正文 | 40px           | 保持比例          | meta + H1 后进入正文       |

### 间距基准

| **间距** | **典型用途**                                        |
|----------|-----------------------------------------------------|
| 2–6px    | 标签内部、FAQ 问答之间、作者姓名与简介。            |
| 8–12px   | 列表项、链接组、meta 项间距、标题与简短说明。       |
| 16–24px  | 段落、表格单元格、blockquote 内边距、代码块。       |
| 28–40px  | 子区块、卡片内边距、文章 header、FAQ/CTA 容器。     |
| 48–56px  | 主章节、References、CTA、作者、Related 的垂直分隔。 |

### 圆角与阴影

| **Token**    | **值**                         | **使用范围**                                                  |
|--------------|--------------------------------|---------------------------------------------------------------|
| tc-radius    | 22px                           | blockquote 右侧、pre、Mermaid 容器、按钮、reading-time pill。 |
| tc-radius-lg | 28px                           | CTA、FAQ 等大型卡片容器。                                     |
| shadow-sm    | 0 1px 3px rgba(15,23,42,.06)   | FAQ 卡片，轻微抬升。                                          |
| shadow-md    | 0 10px 30px rgba(15,23,42,.07) | 已定义但样例未使用；保留给较大悬浮内容。                      |
| shadow-lg    | 0 8px 24px rgba(0,0,0,.12)     | 已定义但样例未使用；不应随意启用。                            |

## 05 核心组件规范

### 文章头部 Article Header

- **顺序固定：**作者 → 发布日期 → 阅读时长 → H1。

- **Meta：**flex 横排，gap 12px，14px；reading time 使用 gray-100 胶囊。

- **H1：**深灰、800、紧行高、负字距；不在文章正文重复显示 CMS 默认标题。

### Lead / 直接答案段

- **位置：**紧跟每个 H2。

- **样式：**19px、500、行高 1.6、gray-800。

- **内容：**1–2 句直接回答章节问题，尽量可单独成为精选摘要或 AI 搜索答案。

### 链接

- **默认：**tc-red、无下划线，仅保留透明 1px 底边。

- **Hover：**底边变为 tc-red；不改变字号、字重或布局。

- **外链：**target="_blank" + rel="noopener"。

### 引用 Blockquote

| **属性** | **规范**                                             |
|----------|------------------------------------------------------|
| 结构     | 左侧 3px 红线；右上、右下 22px 圆角。                |
| 容器     | gray-100 背景；16px 24px 内边距；上下 28px。         |
| 文字     | 16px、italic、gray-700；最后一段无下边距。           |
| 语义     | 使用 blockquote + cite；可补充 Schema CreativeWork。 |

### 代码

| **类型** | **规范**                                                         |
|----------|------------------------------------------------------------------|
| 行内代码 | gray-100 背景；2px 6px；3px 小圆角；14px mono；red-dark。        |
| 代码块   | gray-900 背景；gray-100 文字；20px 24px；22px 圆角；可横向滚动。 |

### 表格

- **容器：**figure.table-wrap，允许横向滚动，避免移动端压缩。

- **表头：**gray-900 / white，13px，600，全大写，0.5px 字距。

- **单元格：**10px 16px，底边 gray-200；正文 15px。

- **斑马纹：**偶数行 gray-100。

- **用途：**对比矩阵、预算/周期/优先级、步骤差异；避免用表格做纯布局。

### CTA 卡片

| **属性** | **规范**                                                       |
|----------|----------------------------------------------------------------|
| 容器     | 上 56px；36px 40px；gray-900 → #2a2a2a 135° 渐变；28px 圆角。 |
| 标题     | 22px、white；上边距清零。                                      |
| 说明     | 16px、gray-200；段后 20px。                                    |
| 按钮     | 12px 32px；red；white；22px 圆角；600 / 15px。                 |
| Hover    | 背景 red-dark；向上移动 1px；0.2s ease。                       |
| 语气     | 明确下一步，但不过度促销；承接文章主题。                       |

### FAQ 卡片

| **属性** | **规范**                                               |
|----------|--------------------------------------------------------|
| 容器     | white；1px gray-200；28px 圆角；shadow-sm；36px 40px。 |
| 问题     | 700、gray-900、可点击光标；与答案间 6px。              |
| 答案     | 16px、gray-700。                                       |
| 节奏     | FAQ item 间距 24px；最后一项为 0。                     |
| 语义     | FAQPage / Question / Answer 与 JSON-LD 内容保持一致。  |

### 作者与相关文章

- **作者：**顶部 1px gray-200；头像 48×48 圆形；姓名 14px/600；简介 gray-500。

- **相关文章：**纵向排列，gap 8px；标题 18px gray-700；链接 15px red。

## 06 数据可视化与图表

样例使用 Mermaid 作为流程图实现方案。视觉上保持“信息图而非装饰图”：边框轻、背景浅、文本清晰、容器可滚动，并优先保证移动端可读。

### Mermaid 容器

| **元素**    | **规范**                                                   |
|-------------|------------------------------------------------------------|
| figure      | class="visual-mermaid"；上下 32px。                        |
| figcaption  | 16px / 700 / gray-900；下 12px。                           |
| container   | 1px gray-200；22px 圆角；max-height 700px；overflow auto。 |
| diagram pre | gray-100；16px；13px；无外边距。                           |
| 初始化      | theme: neutral；useMaxWidth: true；htmlLabels: true。      |

### 图表语言

- **使用问题驱动标题：**例如“Match Your Niche to the Right Format”，而非“Figure 1”。

- **节点文字短而完整：**先说明判断，再输出明确建议与格式。

- **颜色克制：**优先 neutral 主题；品牌红只用于关键路径或高亮，不把每个节点都染红。

- **可替代文本：**复杂图表必须在正文中提供等价文字说明。

### 数据表与统计卡的建议扩展（推断）

> **可新增，但需保持同一语言**
>
> 未来可加入“关键统计卡”组件：white 或 gray-100 背景、gray-200 边框、22px 圆角；数字 gray-900，单位 gray-700，品牌红仅做小标签或趋势箭头。

## 07 图像与主视觉

当前 HTML 未展示正文图片，但 Open Graph 元数据提供了可用线索：社交主视觉为 1280×720，alt 描述为“Creative professional designing linkable content assets, flat Memphis illustration style”。因此以下图像规范属于“基于样例的初版推断”。

### 主视觉建议

| **项目** | **初版规范**                               | **证据等级** |
|----------|--------------------------------------------|--------------|
| 画幅     | 16:9，首选 1280×720；社交卡大图。          | 明确         |
| 风格     | 扁平 Memphis 插画；现代、几何、编辑感。    | 推断         |
| 主题     | 人物 + 工作场景 + 内容/数据/SEO 抽象元素。 | 推断         |
| 色彩     | 以中性灰为基底，砖红点题；避免高饱和多色。 | 推断         |
| 构图     | 留出标题/裁切安全区；主体不贴边。          | 推断         |
| Alt      | 描述主体、动作、媒介和风格，不堆关键词。   | 明确         |

### 不建议

- 通用图库中夸张握手、箭头增长、会议摆拍。

- 3D 金属、霓虹赛博、强光效或与正文无关的抽象背景。

- 把大量正文、数据或小字号文字直接烘焙进主视觉。

- 每篇文章更换完全不同的插画体系。

> **待确认项**
>
> 需要 Logo 源文件、既有社交封面、首页视觉和至少 3 篇文章缩略图，才能正式定义插画线条、人物比例、背景纹理、图标风格与裁切规则。

## 08 交互、响应式与打印

### 交互

| **对象**       | **默认**       | **Hover / 行为**                     |
|----------------|----------------|--------------------------------------|
| 正文链接       | red，无下划线  | 出现 red 底边，0.2s ease。           |
| CTA 按钮       | red / white    | red-dark，translateY(-1px)。         |
| FAQ 问题       | 700 / gray-900 | cursor:pointer；样例未定义展开动画。 |
| Mermaid / 表格 | 完整宽度       | 小屏横向滚动，不压缩内容。           |

### 移动端 ≤768px

| **元素**  | **移动规则**                     |
|-----------|----------------------------------|
| H1        | 固定 28px。                      |
| H2        | 21px；上边距降为 36px。          |
| H3        | 使用正文响应式字号。             |
| Container | 32px 16px 60px。                 |
| CTA / FAQ | 内边距从 36×40 降至 24×28。      |
| 表格/图表 | 保留原始信息密度，允许横向滚动。 |

### 打印

- **隐藏：**CTA、相关文章。

- **背景：**body 改为 white，文字 black。

- **链接：**black + black 底边，确保纸面可辨认。

- **标题去重：**隐藏 WordPress 默认 .wp-block-post-title / .entry-title。

## 09 内容结构与语义标记

虽然本文件以视觉规范为主，但该样例的“品牌风格”与结构化内容强绑定。后续文章应同时遵循视觉层级和语义层级，否则即使 CSS 一致，也会失去 TraffiClimb 的内容体验。

### 推荐文章顺序

1. **Meta 信息 + H1。**作者、日期、阅读时长；主标题明确利益点。

2. **场景化开篇。**用数据、对比或真实问题建立紧迫感。

3. **H2 + lead 直接答案。**每节先答，再解释。

4. **证据/步骤/矩阵。**穿插表格、引用、列表或 Mermaid。

5. **References。**统一编号，真实来源与正文引用对应。

6. **主题 CTA。**承接正文，不突然跳转到强销售。

7. **FAQ。**覆盖成本、选择、周期、失败情形等搜索问题。

8. **作者 + 相关文章。**建立可信度和内容内循环。

### 结构化数据

| **类型**                 | **要求**                                                                              |
|--------------------------|---------------------------------------------------------------------------------------|
| Organization + WebSite   | 站点层稳定复用，Logo、sameAs、contactPoint 统一维护。                                 |
| Article                  | headline、description、author、datePublished、dateModified、wordCount、timeRequired。 |
| hasPart                  | H2 章节名称与说明应和页面内容一致。                                                   |
| HowToSection / HowToStep | 步骤型章节用明确步骤语义，不滥用。                                                    |
| FAQPage                  | JSON-LD 与页面可见 FAQ 完全一致。                                                     |
| BreadcrumbList           | Home → Blog → Category → Article。                                                    |

### SEO 元数据一致性

- Title、meta title、OG title、Twitter title 语义一致。

- Description、OG description、Twitter description 语义一致但可按长度微调。

- Canonical、OG URL、mainEntityOfPage 使用同一最终 URL。

- OG/Twitter 图片、尺寸和 alt 必须完整。

- 发布日期、修改日期在 HTML、Open Graph、JSON-LD 中一致。

## 10 无障碍与质量底线

### 必须满足

- **语义标题：**H1 唯一；H2/H3 不跳级。

- **色彩对比：**正文 gray-900 / bg；辅助 gray-700；避免用 gray-500 承载重要长文。

- **链接可辨识：**hover 有底边；建议未来补充 keyboard focus 样式。

- **表格：**必须有 thead/th；复杂表格补 caption 或 figcaption。

- **图像：**有信息价值的图片写准确 alt；装饰图使用空 alt。

- **图表：**正文提供等价说明；容器可滚动但不隐藏内容。

- **运动：**现有动效仅 1px 位移；未来新增动效应尊重 prefers-reduced-motion。

### 当前样例的改进机会

| **项目** | **建议**                                                |
|----------|---------------------------------------------------------|
| 键盘焦点 | 为 a、button、FAQ 可交互元素增加 2px 可见 focus ring。  |
| FAQ 交互 | 若可折叠，使用 button + aria-expanded + aria-controls。 |
| 作者头像 | 真实头像使用 img + alt；纯装饰占位使用 aria-hidden。    |
| 引用来源 | cite 可增加链接或更完整来源信息。                       |
| Mermaid  | 提供 aria-label 或紧邻的文字摘要。                      |

## 11 制作检查清单

### 视觉检查

- 页面只使用已定义的品牌红、灰阶、白色和背景色。

- H1/H2/H3、lead、正文、meta 均符合字号与间距层级。

- 大卡片使用 28px 圆角，小组件使用 22px；无临时圆角。

- 品牌红未被大面积铺满，正文保持深灰。

- 表格、引用、代码、CTA、FAQ 的样式与本规范一致。

- 移动端表格和 Mermaid 可横向滚动且不截断。

### 内容与 SEO 检查

- 每个 H2 后有一段可独立理解的 lead。

- 正文中的数据、引用与 References 编号一致。

- Article / FAQ / Breadcrumb JSON-LD 与可见内容一致。

- Title、description、canonical、OG、Twitter Card 完整。

- 主视觉为 1280×720，并填写具体、自然的 alt。

### 发布前 QA

1. 桌面宽度检查：1440、1280、1024。

2. 移动宽度检查：768、430、390、360。

3. 测试链接 hover、键盘 focus、CTA、FAQ 和外链。

4. 打印预览：CTA/Related 隐藏，链接可辨认。

5. 验证 Schema 与页面文本、日期和 URL 一致。

> **决策规则**
>
> 当新需求不在本规范中时，先复用最接近的现有组件；只有在至少 3 篇内容会重复使用时，才新增 token 或组件。
