## 二、部署步骤

### 1. 安装系统依赖

```bash
# Ubuntu/Debian
sudo apt update
sudo apt install -y python3.12 python3.12-venv python3-pip git nginx

# CentOS/RHEL
sudo dnf install -y python3.12 git nginx
```

### 2. 克隆代码

```bash
sudo mkdir -p /opt/blog-writer
sudo chown $USER:$USER /opt/blog-writer
cd /opt/blog-writer
git clone git@github.com:ywy-hub-cn/blog_writer.git .
```

### 3. 创建虚拟环境并安装依赖

```bash
cd /opt/blog-writer
python3.12 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

### 4. 配置环境变量

```bash
cp .env.example .env
sudo nano .env
```

**必填项**：
```env
LLM_API_KEY=sk-你的密钥
LLM_BASE_URL=https://api.deepseek.com/v1
BLOG_WRITER_ADMIN_PASSWORD=你的强密码
BLOG_WRITER_MODE=production
```

**生产环境建议（Java 服务对接 + 运营浏览器访问）**：
```env
# —— Java 后端对接 ——
RESPONSE_CASE=camel
BLOG_WRITER_API_TOKEN=服务间固定Token
BLOG_WRITER_TASK_AUTH=optional
BLOG_WRITER_HEALTH_ENVELOPE=true
# 定时窗口（scheduledAt + scheduledEndAt）依赖进程在线
BLOG_WRITER_SCHEDULER_INTERVAL_SECONDS=15

# —— 状态存储：默认 memory（运营本地设备只需浏览器，无需 Redis）——
BLOG_WRITER_STATE_BACKEND=memory
REVIEW_EVENT_BACKEND=memory
# 即使公司其他服务共用 REDIS_URL，也不要给 blog-writer 自动切 Redis；
# 仅当需要跨进程持久化登录 Token / 多副本时再显式设 redis：
# BLOG_WRITER_STATE_BACKEND=redis
# REDIS_URL=redis://可连通的地址:6379/0

# —— 数据库 ——
DB_BACKEND=postgres
DB_HOST=127.0.0.1
DB_PORT=5432
DB_NAME=blog_writer
DB_USER=blog_writer
DB_PASSWORD=数据库密码

CORS_ORIGINS=https://your-domain.com
MAX_CONCURRENT_TASKS=5
```

**架构说明**：
- **Java 服务**：用 `X-API-Key: BLOG_WRITER_API_TOKEN` 调 `/api/v1/tasks/start` 等接口；字段用 camelCase（`scheduledAt` / `scheduledEndAt`）
- **定时任务**：调度器跑在 **本进程内**，容器/ systemd 须 `restart: unless-stopped` / `enable` 保活；关机期间到点任务开机后会补扫。结束时间到期会 `task.paused`/`task.cancelled`（`reason=schedule_end`）
- **运营人员**：本地电脑浏览器打开 Web UI，**不需要安装 Redis**，不需要 VPN 到 Redis
- **blog-writer 进程**：单实例部署（任务状态在内存），禁止水平扩容多副本（除非配 Redis 审核总线）

### 5. 配置数据库（PostgreSQL，可选）

```bash
sudo -u postgres psql
```
```sql
CREATE DATABASE blog_writer;
CREATE USER blog_writer WITH PASSWORD '你的密码';
GRANT ALL PRIVILEGES ON DATABASE blog_writer TO blog_writer;
\q
```

### 6. 配置systemd服务

```bash
sudo cp deploy/blog-writer.service /etc/systemd/system/
sudo nano /etc/systemd/system/blog-writer.service  # 根据实际路径修改
sudo systemctl daemon-reload
sudo systemctl enable blog-writer
sudo systemctl start blog-writer
```

### 7. 配置Nginx反向代理

```bash
sudo cp deploy/nginx.conf /etc/nginx/sites-available/blog-writer
sudo ln -s /etc/nginx/sites-available/blog-writer /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

### 8. 验证部署

```bash
# 检查服务状态
sudo systemctl status blog-writer

# 健康检查
curl http://localhost:8000/health

# 查看日志
sudo journalctl -u blog-writer -f
```

## 三、GitHub Actions 自动部署配置

项目已配置CI/CD流水线（`.github/workflows/ci.yml`），部署job为**手动触发**。

### 配置GitHub Secrets

在GitHub仓库 → Settings → Secrets and variables → Actions 中添加：

| Secret名 | 说明 | 示例 |
|----------|------|------|
| `DEPLOY_HOST` | 服务器IP | `192.168.1.100` |
| `DEPLOY_USER` | SSH用户名 | `deploy` |
| `DEPLOY_SSH_KEY` | SSH私钥（私钥内容，不是公钥） | `-----BEGIN OPENSSH PRIVATE KEY-----...` |
| `DEPLOY_PORT` | SSH端口 | `22` |
| `DEPLOY_PATH` | 服务器上项目路径 | `/opt/blog-writer` |

### 触发部署

1. GitHub仓库 → Actions → CI/CD Pipeline → Run workflow
2. 选择main分支，点击运行
3. lint/test/security/build通过后，deploy job会执行SSH部署

### 部署流程

```
git fetch origin → git reset --hard origin/main → pip install → systemctl restart
```

```bash
sudo systemctl restart blog-writer
```

## 五、常见问题

**Q: 服务启动失败？**
A: `sudo journalctl -u blog-writer -n 50` 查看错误，常见是.env未配置或端口被占用。

**Q: 任务一直queued？**
A: 检查MAX_CONCURRENT_TASKS配置，或调大并发数后重启。

**Q: LLM调用失败？**
A: 检查LLM_API_KEY和LLM_BASE_URL是否正确，网络是否能访问大模型API。

**Q: 自动部署失败？**
A: 检查GitHub Secrets是否配置正确，服务器SSH是否能连通，DEPLOY_PATH是否存在。
