# Blog-Writer 数据库表结构说明

> 数据库默认使用 SQLite（`instance/blog_writer.db`），企业部署可切换 PostgreSQL / MySQL。
> 程序启动时自动建表，无需手动执行 DDL。

---

## 表总览

| 序号 | 表名 | 用途 | 记录数预估 |
|------|------|------|-----------|
| 1 | `tasks` | 任务状态主表 | 每条任务1行 |
| 2 | `task_logs` | 任务执行日志 | 每任务几十~几百行 |
| 3 | `node_definitions` | 节点定义缓存 | 约18行（固定） |
| 4 | `brands` | 品牌元数据 | 每个品牌1行 |
| 5 | `audit_log` | 操作审计日志 | 按需增长 |
| 6 | `rate_limit_audit` | 限流审计 | 按需增长 |
| 7 | `schema_version` | Schema版本 | 1行 |

---

## 1. tasks — 任务主表

任务状态、进度、输入输出的核心存储。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `task_id` | TEXT | PRIMARY KEY | 任务唯一ID，格式 `task_YYYYMMDD_HHMMSS_xxxxxx` |
| `status` | TEXT | NOT NULL DEFAULT 'pending' | 任务状态：pending/running/paused/waiting_review/completed/failed/cancelled |
| `mode` | TEXT | NOT NULL DEFAULT 'auto' | 运行模式：auto/supervised/manual |
| `current_step` | INTEGER | NOT NULL DEFAULT 0 | 当前执行到第几步 |
| `total_steps` | INTEGER | NOT NULL DEFAULT 0 | 总步骤数 |
| `start_time` | TEXT | | 启动时间 ISO8601 |
| `end_time` | TEXT | | 结束时间 ISO8601 |
| `brand_path` | TEXT | | 品牌路径，如 `./brands/my-brand` |
| `keywords` | TEXT | | 任务关键词 |
| `user_note` | TEXT | | 用户附加要求 |
| `brand_site_url` | TEXT | | 品牌网站URL |
| `step_files` | TEXT | | JSON数组，节点文件列表 |
| `completed_steps` | TEXT | | JSON数组，已完成节点文件名 |
| `results` | TEXT | | JSON数组，各节点执行结果 |
| `outputs` | TEXT | | JSON对象，节点间传递的数据 |
| `retry_counts` | TEXT | | JSON对象，各节点重试次数 |
| `review_node` | TEXT | | 当前等待审核的节点文件 |
| `review_node_name` | TEXT | | 当前等待审核的节点名称 |
| `extra` | TEXT | | JSON对象，扩展字段（如 `priority`、`batch_id`） |
| `updated_at` | TEXT | NOT NULL | 最后更新时间 |

**示例数据：**

```json
{
  "task_id": "task_20260818_091543_a3eaa4",
  "status": "completed",
  "mode": "auto",
  "current_step": 12,
  "total_steps": 12,
  "start_time": "2026-08-18T09:15:43.123456",
  "end_time": "2026-08-18T09:32:15.987654",
  "brand_path": "./brands/sms-boosting",
  "keywords": "SMS API integration",
  "user_note": "偏向技术受众，突出API易用性",
  "brand_site_url": "https://example.com",
  "step_files": "[\"S000-startup.json\",\"S001-bid-infer.json\",\"S002-content-prd.json\"]",
  "completed_steps": "[\"S000-startup.json\",\"S001-bid-infer.json\"]",
  "results": "[{\"step\":\"S000-startup.json\",\"status\":\"success\"}]",
  "outputs": "{\"bid\":\"sms-api-integration\",\"title\":\"...\"}",
  "retry_counts": "{\"S004-draft.json\":1}",
  "review_node": "",
  "review_node_name": "",
  "extra": "{\"priority\":2,\"batch_id\":\"batch_20260826_001\"}",
  "updated_at": "2026-08-18T09:32:15.987654"
}
```

## 2. task_logs — 任务执行日志

每个任务的运行日志，按时间追加。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 自增ID |
| `task_id` | TEXT | NOT NULL, FK→tasks | 关联任务ID，级联删除 |
| `log_entry` | TEXT | NOT NULL | 日志内容 |
| `created_at` | TEXT | NOT NULL | 记录时间 |

**示例数据：**

```
id=1
task_id=task_20260818_091543_a3eaa4
log_entry=🚀 任务启动: SMS API integration (mode=auto, brand=./brands/sms-boosting)
created_at=2026-08-18T09:15:43.200000
```

---

## 3. node_definitions — 节点定义缓存

工作流节点的JSON定义缓存，加速加载。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `node_id` | TEXT | PRIMARY KEY | 节点ID，如 `step.blog.writer.startup` |
| `name` | TEXT | | 节点显示名，如 `启动初始化` |
| `exec_type` | TEXT | NOT NULL | 执行类型：agent_action/pure_code/human_review |
| `seq` | INTEGER | DEFAULT 0 | 执行顺序号 |
| `definition` | TEXT | NOT NULL | 节点完整JSON定义 |
| `updated_at` | TEXT | NOT NULL | 更新时间 |

**示例数据：**

```
node_id=step.blog.writer.startup
name=启动初始化
exec_type=agent_action
seq=0
definition={"id":"step.blog.writer.startup","name":"启动初始化","kind":"agent_action",...}
updated_at=2026-08-18T09:00:00.000000
```

## 4. brands — 品牌元数据

品牌的显示名和存储路径，文件本体在 `brands/{brand_id}/` 目录。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `brand_id` | TEXT | PRIMARY KEY | 品牌英文ID，如 `sms-boosting` |
| `display_name` | TEXT | NOT NULL | 品牌显示名（中文），如 `SMS Boosting` |
| `inner_path` | TEXT | NOT NULL | 内部相对路径，如 `./brands/sms-boosting` |
| `created_at` | TEXT | NOT NULL | 创建时间 |
| `updated_at` | TEXT | NOT NULL | 更新时间 |

**示例数据：**

```
brand_id=sms-boosting
display_name=SMS Boosting
inner_path=./brands/sms-boosting
created_at=2026-08-01T10:00:00.000000
updated_at=2026-08-01T10:00:00.000000
```

## 5. audit_log — 操作审计日志

记录管理员操作、登录、配置变更等。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 自增ID |
| `event_type` | TEXT | NOT NULL | 事件类型：login/config_change/task_create等 |
| `event_source` | TEXT | NOT NULL | 事件来源：api/admin/system |
| `details` | TEXT | | 事件详情JSON |
| `actor` | TEXT | | 操作者标识 |
| `ip_address` | TEXT | | 操作者IP |
| `created_at` | TEXT | NOT NULL | 事件时间 |

**示例数据：**

```
id=1
event_type=login
event_source=api
details={"success":true}
actor=admin
ip_address=127.0.0.1
created_at=2026-08-18T09:15:00.000000
```

## 6. rate_limit_audit — 限流审计

记录触发限流的请求，用于排查和监控。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 自增ID |
| `client_id` | TEXT | NOT NULL | 客户端标识（IP或用户ID） |
| `endpoint` | TEXT | NOT NULL | 接口路径+违规类型 |
| `request_count` | INTEGER | DEFAULT 0 | 窗口内请求数 |
| `window_start` | TEXT | NOT NULL | 限流窗口开始时间 |
| `window_end` | TEXT | NOT NULL | 限流窗口结束时间 |
| `created_at` | TEXT | NOT NULL | 记录时间 |

---

## 7. schema_version — Schema版本

记录当前数据库schema版本，用于迁移判断。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `version` | INTEGER | PRIMARY KEY | schema版本号，当前=1 |
| `applied_at` | TEXT | NOT NULL | 应用时间 |

## 索引

| 索引名 | 表 | 字段 | 用途 |
|--------|-----|------|------|
| `idx_task_logs_task_id` | task_logs | task_id | 按任务查日志 |
| `idx_audit_log_event_type` | audit_log | event_type | 按事件类型查审计 |
| `idx_audit_log_created_at` | audit_log | created_at | 按时间查审计 |
| `idx_tasks_status` | tasks | status | 按状态筛任务 |

## 注意事项

1. **JSON字段**：`step_files`、`completed_steps`、`results`、`outputs`、`retry_counts`、`extra` 存的是JSON字符串，读取时需反序列化
2. **级联删除**：删除task时，`task_logs` 中关联记录自动删除（ON DELETE CASCADE）
3. **自动建表**：程序启动执行 `CREATE TABLE IF NOT EXISTS`，幂等安全
4. **自动迁移**：旧库缺少 `user_note`、`brand_site_url` 字段时自动添加
5. **WAL模式**：SQLite启用WAL提升并发写性能
