# 企业级多Agent人机协同内容运营系统 - AI编程提示词 V3.0

> 版本：v3.0 | 整合优化版 | 适用：Cursor / Trae / Claude Dev
>
> 设计理念：LangGraph编排 + 节点配置化 + 混合执行架构 + 企业级安全

---

## 一、系统定位

企业级多品牌内容运营自动化平台，支持 **3个品牌**（smsboosting云通信、gomodelhub大模型路由、trafficlimb SEO服务）的 **SEO博客 + 社媒内容** 全流程自动化生产、审核、分发、数据闭环。

**核心设计思想：**
- 配置驱动：工作流节点JSON化定义，改流程不用改代码
- 混合执行：纯代码 / 单次LLM / Agent三模式，按需选择，成本最优
- 人机协同：LangGraph原生Interrupt实现断点干预，6个审核节点
- 记忆增强：向量记忆库保证品牌风格统一
- 生产级标准：Docker部署、权限管控、全链路日志、审计留痕

## 二、强制技术栈

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| **编排框架** | LangGraph | 多Agent编排，必须用原生Interrupt + Checkpointer实现断点续跑 |
| **接口层** | FastAPI + Pydantic v2 | RESTful接口，自动生成swagger |
| **大模型** | OpenAI兼容协议 | 对接gomodelhub，base_url: `https://api.gomodelhub.com/v1`，密钥环境变量注入 |
| **关系数据库** | MySQL 8.0 | 业务数据、任务记录、版本日志、用户权限 |
| **缓存** | Redis 7 | 短期任务状态、缓存、分布式锁 |
| **向量库** | Milvus 2.3 | 品牌风格、历史内容、合规规则向量记忆 |
| **对象存储** | MinIO | 静态资源、内容文件、配图 |
| **任务调度** | APScheduler | 定时任务、排期发布 |
| **ORM** | SQLAlchemy 2.0 | 异步优先 |
| **日志** | loguru | 全链路追踪，按天切割 |
| **部署** | Docker Compose | 一键编排，配置全部环境变量注入 |
| **前端** | Vue3 + Element Plus | 运营后台，单页应用 |

## 四、核心模块设计

### 4.1 总调度 Agent（LangGraph编排）

**职责：** 任务拆解、Agent调度、状态流转、异常处理、任务归档

**任务触发方式：**
- 手动触发（后台/API）
- 定时触发（排期任务）
- API触发（第三方系统调用）

**状态管理：**
- 全链路任务状态追踪（LangGraph Checkpointer持久化）
- 支持暂停、继续、终止、打回指定节点重跑
- 失败自动重试（默认3次，可配置），重试失败转人工
- 断点续跑：从失败节点继续，前面结果复用

**异常处理：**
- 节点级重试 + 降级策略
- 失败告警推送（邮件/飞书webhook）
- 死循环检测（recursion_limit限制）

---

### 4.2 五个专项 Agent

#### ① 选题策略 Agent
- **工具：** 关键词挖掘、竞品爬虫、行业热点爬虫、Ahrefs数据对接
- **功能：** 选题池生成、品牌适配筛选、周/月排期、关键词布局规划
- **输出：** 结构化选题清单（核心词、长尾词、难度预估、建议发布时间）

#### ② 内容生产 Agent（最核心）
- **多品牌适配：** 三个品牌独立Prompt模板库 + 风格配置，通用内容一键改写多品牌版本
- **生成流程：** 大纲生成 → 分段正文生成 → SEO优化（关键词密度、内链、Meta）
- **社媒衍生：** 单篇博客自动拆解为 LinkedIn/X/Facebook/EDM 多平台内容
- **记忆调用：** 生成前自动召回品牌风格向量记忆，保证语气统一
- **局部重写：** 支持传入段落ID，仅重写对应章节，不全文重生成

#### ③ 智能审核 Agent
- **三重审核：**
  1. BERT多标签合规分类模型（API调用已有服务）
  2. 敏感词规则引擎（可配置词库，多语言）
  3. 品牌风格相似度校验（向量比对历史优质内容）
- **输出：** 审核报告（风险分、风险点位置、修改建议）
- **风险分级：** 低风险自动通过 / 中风险抽审 / 高风险强制人工审核

#### ④ 多端分发 Agent
- **发布渠道：**
  - WordPress REST API（三个品牌独立配置）
  - LinkedIn / X / Facebook 官方API
- **功能：** 自动格式适配、定时发布、状态回传、失败重试
- **支持人工调整：** 发布时间、平台、账号

#### ⑤ 数据分析 Agent
- **数据回收：** Google Search Console、各社媒平台API，自动抓流量/排名/互动数据
- **报表生成：** 周/月效果报表，内容表现统计
- **策略迭代：** 分析高表现内容特征，自动更新选题偏好、Prompt模板，写入记忆库

### 4.3 混合执行引擎（核心架构创新）

**每个工作流节点JSON中指定 `exec_type` 字段，三种执行模式按需选择：**

| 执行模式 | 说明 | 适用场景 | 成本 | 速度 | 可靠性 |
|---------|------|---------|------|------|--------|
| `pure_code` | 纯Python代码，不调LLM | 格式校验、数据统计、敏感词检测、文件操作 | 0 | ⚡极快 | 100% |
| `llm_completion` | 单次LLM调用，无工具 | 内容打分、格式转换、简单分类、摘要生成 | 低 | ⚡快 | 高 |
| `agent_action` | ReAct多轮 + 工具调用 | 复杂生成、多步推理、需要读写文件搜网页 | 高 | 🐢慢 | 中 |

**调度逻辑：**
```
LangGraph节点执行:
  读取节点配置 → 判断exec_type
    → pure_code: 直接跑对应Python函数
    → llm_completion: 拼prompt → 一次调LLM → 解析结果
    → agent_action: 启动ReAct循环 → 多轮工具调用 → 完成
```

**多模型路由：**
- 配置文件支持多模型（default / fast / strong）
- 每个节点可单独指定用哪个模型
- 生成类用强模型，审核类用快模型，成本优化50%+

---

### 4.4 节点配置化设计

**所有工作流步骤用JSON定义，存在数据库，支持后台可视化编辑，热更新不用重启：**

```json
{
  "node_id": "content_draft",
  "name": "正文写作",
  "agent_type": "content_production",
  "exec_type": "agent_action",
  "llm_model": "strong",
  "max_iterations": 20,
  "timeout_minutes": 15,
  "retry_count": 3,
  "is_interrupt_point": true,
  "interrupt_config": {
    "review_role": ["editor", "compliance"],
    "can_skip": false,
    "timeout_hours": 24
  },
  "input_schema": {...},
  "output_schema": {...},
  "prompt_template": "...",
  "tools": ["read_file", "write_file", "web_search", "run_python"],
  "checks": [...]
}
```

**节点管理功能：**
- 节点增删改查，可视化JSON编辑器
- 节点版本管理，修改留痕，支持回滚
- 节点测试：单独跑某节点验证效果
- 节点导入导出

## 五、人机协同体系（核心必做）

### 5.1 六个断点干预节点（基于LangGraph Interrupt）

| 节点 | 干预内容 | 默认类型 |
|------|---------|---------|
| 选题确认 | 增删关键词、改选题方向、调排期 | 可选跳过 |
| 大纲确认 | 改章节结构、调关键词布局、改Prompt、调篇幅 | 强制审核 |
| 初稿确认 | 改内容、调语气、指定段落重写、补卖点 | 强制审核 |
| 合规审核 | 改违规内容、调规则、标风险等级、豁免通过 | 强制审核 |
| 发布确认 | 改发布时间、增减平台、切账号 | 可选跳过 |
| 效果复盘 | 确认效果数据、更新策略 | 可选跳过 |

**节点类型可配置：** 强制审核 / 可选跳过，每个品牌独立设置

### 5.2 干预动作

1. **直接通过** → 继续往下执行
2. **修改参数后续跑** → 更新状态，从当前节点继续
3. **打回指定节点重跑** → 回到某节点重新执行，后续节点结果清空

### 5.3 版本与审计

- 每次人工修改自动生成版本号，保存修改前后快照
- 记录：操作人、时间、修改字段、修改原因
- 支持版本对比（diff）
- 所有操作日志不可删除，符合审计要求

### 5.4 通知中心

- 待办实时推送：邮件、飞书/企业微信webhook
- 超时升级：24小时未处理自动升级提醒
- 异常告警：任务失败、发布异常、高风险内容自动告警

## 六、安全与权限体系（企业级标准）

### 6.1 RBAC角色权限

| 角色 | 权限范围 |
|------|---------|
| **运营人员** | 启动任务、查看任务、内容审核、发布操作 |
| **合规人员** | 合规审核、规则配置、风险查看 |
| **内容主管** | 以上全部 + 选题管理 + 数据查看 |
| **系统管理员** | 全部权限 + 节点配置 + 系统配置 + 用户管理 |

- 接口级权限控制，每个接口声明所需角色
- 前端按角色动态显示菜单和按钮
- 操作日志记录所有敏感操作

### 6.2 敏感信息保护

- 所有API密钥、数据库密码通过环境变量注入，不写代码
- 配置页面密钥显示掩码（前3后4），修改需重新输入
- 日志自动脱敏所有密钥、密码、token
- 数据库中敏感字段可选加密存储

### 6.3 系统安全

- JWT鉴权，token过期自动刷新
- 接口限流（按用户/IP）
- CORS配置，限制允许域名
- SQL注入防护（ORM + 参数化查询）
- XSS防护（输出转义）
- 文件上传校验（类型、大小、内容检测）

### 6.4 数据安全

- 数据库定时备份
- MinIO对象存储版本控制
- 操作日志永久留存
- 敏感操作二次确认（删除、批量发布等）

## 七、记忆系统

### 7.1 向量记忆库（Milvus）

| 库名 | 内容 | 用途 |
|------|------|------|
| 品牌风格库 | 各品牌优质文章样本、语气调性描述 | 生成前召回，保证风格统一 |
| 优质内容库 | 历史高表现文章向量 | 参考写作、相似度校验 |
| 合规规则库 | 合规案例、禁用表述 | 审核时召回比对 |
| 效果样本库 | 高转化/高流量内容特征 | 选题和生成时参考 |

### 7.2 记忆机制

- **召回：** 每个Agent执行前，自动召回相关Top-K记忆，注入prompt
- **更新：** 审核通过的内容、人工修改的优质版本，自动入库
- **迭代：** 定期聚类分析，淘汰低质量记忆，更新记忆库
- **隔离：** 三个品牌记忆库完全隔离，互不干扰

## 十二、编码规范

1. **模块化**：每个Agent独立模块，接口解耦，可单独迭代
2. **配置分离**：所有敏感信息环境变量读取，提供.env.example
3. **错误处理**：所有接口、工具调用都有异常捕获、重试、结构化错误
4. **日志规范**：loguru全链路日志，包含task_id、node_name、耗时、错误信息
5. **接口规范**：FastAPI自动生成swagger，Pydantic校验参数
6. **代码注释**：核心逻辑、复杂算法必须有中文注释，函数必须有docstring
7. **类型提示**：所有函数参数和返回值都要有类型注解
8. **测试**：核心模块要有单元测试
