工作日报 - 第四天（Bug审查与加固阶段）

一、今日工作内容

1. 认证系统关键 bug 修复：
   - 修复 LocalAuthProvider 与 AuthManager 哈希算法不一致问题：原 LocalAuthProvider 使用 SHA256，而 AuthManager 使用 bcrypt，导致 AuthManager 设置的密码在 LocalAuthProvider 路径下永远无法通过验证。将 _hash_password 委托给 AuthManager，新增 _verify_password 方法替代直接哈希比较，同时兼容遗留 SHA256。
   - 补充端到端验证：确认 bcrypt 新密码、正确密码、错误密码、遗留 SHA256 四类场景均通过。

2. 协程泄漏 bug 修复：
   - 修复 _schedule_resume_from_current 方法中 _safe_resume_workflow 协程未被 await 的问题：原代码在 RuntimeError 分支无条件创建 coro，但仅当 main 循环可用时才使用，否则协程对象被丢弃导致 RuntimeWarning。将 coro 创建移入条件分支内，仅在确实需要时创建。

3. Token 统计 key 统一：
   - 修正 hybrid_executor.py 中 6 处 token_usage key 不一致问题：将错误/空操作返回值中的 "total_tokens" 统一为 "total_tokens_used"，与成功路径及消费者读取逻辑保持一致。
   - 同步修复测试 mock 中的 key 命名。

4. 测试与环境完善：
   - 安装缺失依赖 pytest-asyncio、fastapi、python-multipart。
   - 全量测试 256 passed，无回归。

二、发现的问题与解决

- LocalAuthProvider SHA256 与 AuthManager bcrypt 哈希不兼容：认证路径分叉导致密码校验必然失败，统一委托 AuthManager 解决。
- 协程泄漏导致 RuntimeWarning：任务续跑调度异常时协程对象未被消费，移入条件分支按需创建解决。
- token_usage key 命名不一致：错误/空操作返回值使用 "total_tokens" 而消费者读取 "total_tokens_used"，统一为 "total_tokens_used"。

三、工作效果

修复 3 个关键运行时 bug，认证系统与协程调度稳定性显著提升。全量测试 256 passed，为后续功能迭代提供可靠基础。
