## 环境与依赖

```bat
cd blog-writer-main
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

- **必须使用项目 `.venv`**，不要往全局 Anaconda/系统 Python 装依赖。
- `requirements.txt` 含运行时 + 测试/开发工具：
  - 数据库：`psycopg2-binary`（Postgres）、`pymysql`（MySQL）；默认 sqlite 无需额外驱动
  - 状态外置（可选）：`redis>=5`
  - 密码哈希：`bcrypt>=4,<5`（管理员口令；兼容旧 SHA256 升级）
- 环境变量模板：`.env.example`；配置模板：`config.json.example`（复制为 `blog_writer/config.json` 或通过 `BLOG_WRITER_CONFIG` 指定）。

启动：

```bat
.venv\Scripts\python.exe run.py
```

## 架构概述

```
公司统一平台（用户/权限/计费/监控）
        │  HTTP + Bearer/X-API-Key + Webhook
        ▼
Blog-Writer API（FastAPI）
  blog_writer/main.py
        │
        ▼
WorkflowService（任务编排 / 审核 / 断点续跑）
  + WorkflowRouter（registry.routing）
        │
        ▼
registry.json + nodes/*.json + brands/ + LLM
        │
        ▼（S010/S011）
tools/blog-writer/assemble_publish.py
tools/blog-writer/publish_to_wp.py
```

- **服务入口**：`uvicorn blog_writer.main:app`
- **推荐基址**：`/api/v1`
- **兼容基址**：`/api`（同路由，仍可用）
- **编排**：按 `registry.json` → `routing` 的 `on_pass` / `on_fail` / `mode_override` / `risk_based` 导航（非纯线性）
- **生产进程**：默认 **单 worker** / Compose `replicas: 1`
  - Token / Webhook 注册：可经 `REDIS_URL` 外置（见下）
  - 任务真相源：DB（sqlite/postgres）；运行中审核 `Event` 仍为进程内存
  - 终态任务内存态会延迟清理（默认 5 分钟），列表/详情以 DB 为准
  - **未充分外置审核会话前，勿水平扩展多副本**

## 鉴权（对接必读）

**2026-08-12 更新**：品牌接口和任务接口已改为**免登录**（运营使用场景），未登录时自动使用默认运营用户（operator/admin）。管理员接口（节点CRUD、系统配置）仍需登录。

| 接口类别 | 鉴权要求 | 说明 |
|----------|----------|------|
| 品牌接口 `/api/v1/brands*` | 免登录 | 列表、上传均公开 |
| 任务接口 `/api/v1/tasks*` | 免登录 | 启动/列表/详情/日志/暂停/恢复/取消/续跑/审核 |
| 管理员接口 `/api/v1/admin*` | 需登录 | 节点CRUD、系统配置、LLM测试 |
| 认证接口 `/api/v1/auth*` | - | 登录/登出/改密 |

已认证方式（管理员接口用）：

| 方式 | Header | 说明 |
|------|--------|------|
| 服务 Token | `Authorization: Bearer <token>` 或 `X-API-Key: <token>` | 环境变量 `BLOG_WRITER_API_TOKEN`，平台服务间调用推荐 |
| SSO | Bearer SSO token | 配置 `security.sso.enabled` 后可用 |
| 管理员 JWT | `Authorization: Bearer <jwt>` | `POST /api/v1/auth/login`（仅 password） |

未认证访问管理员接口返回 **HTTP 401**，body 仍为统一结构 `{code,message,data,timestamp}`。

管理员密码存储为 **bcrypt**；若配置中仍是旧版 SHA256 哈希，登录成功后会自动升级。

单步执行受 `workflow.step_timeout_minutes` 约束（默认 30 分钟）；超时记 error 并按重试 / fail-closed 处理。

整任务默认**无**总超时（避免 `waiting_review` / 长链路被 1h 误杀）；若需硬上限可设环境变量 `BLOG_WRITER_TASK_TIMEOUT_SECONDS`。

## 统一响应

成功示例：

```json
{
  "code": 0,
  "message": "success",
  "data": { },
  "timestamp": "2026-08-03T16:00:00"
}
```

约定：

- **HTTP 状态码真实**：401/403/404/422/429/500 不再被改写成 200（便于平台熔断与重试）
- **业务码**：`code==0` 成功；非 0 见 `ErrorCode`（如 4002 认证失败、4041 资源不存在）
- 可选：`RESPONSE_CASE=camel` 将字段转为 camelCase

## HTTP API（推荐）

### 0. 品牌管理（免登录）

**获取品牌列表**  
`GET /api/v1/brands`

响应：
```json
{
  "code": 0,
  "data": {
    "brands": [
      {"display_name": "SMS Boosting", "inner_path": "./brands/sms-boosting"}
    ],
    "total": 1
  }
}
```

**上传品牌资料**  
`POST /api/v1/brands/upload`（multipart/form-data）

| 字段 | 类型 | 说明 |
|------|------|------|
| `display_name` | string | 品牌中文显示名（自动转拼音生成brand_id） |
| `files` | File[] | 多个 .md/.txt 文件，单文件≤10MB |

重复 brand_id 直接覆盖目录，不做版本备份。

### 1. 启动任务

`POST /api/v1/tasks/start`

```json
{
  "brandPath": "brands/sms-boosting",
  "keywords": "SMS API",
  "mode": "supervised",
  "userNote": "Technical audience",
  "brandSiteUrl": "https://example.com",
  "callbackUrl": "https://platform.example.com/hooks/blog-writer",
  "callbackSecret": "optional-hmac-secret"
}
```

也可用 snake_case 字段名（`brand_path` 等）。

响应 `data` 含 `task_id`、`status=started`。

### 2. 查询状态

`GET /api/v1/tasks/{task_id}`

关注终态：`completed` / `failed` / `rejected` / `cancelled` / `completed_partial`。  
**自 2026-08-04 起**：步骤重试耗尽且无法按 `on_fail` 回跳时，任务会进入 **`failed`**（不再跳过失败步骤继续跑完）。

### 3. 任务日志

`GET /api/v1/tasks/{task_id}/logs`

### 4. 人工审核

`GET /api/v1/tasks/reviews/pending`  
`POST /api/v1/tasks/{task_id}/review`

```json
{ "decision": "approve", "modifications": {} }
```

`decision`：`approve` | `reject` | `modify` | `retry`

- `reject`：优先按节点 `routing.on_fail` 回跳（如退回 BID/正文）；无回跳目标则任务 `rejected`
- `retry`：重跑当前审核相关步骤

### 5. 生命周期

- `POST /api/v1/tasks/{task_id}/pause`
- `POST /api/v1/tasks/{task_id}/resume`
- `POST /api/v1/tasks/{task_id}/cancel`
- `POST /api/v1/tasks/{task_id}/resume-from`
- `POST /api/v1/tasks/{task_id}/rerun-from`
- `POST /api/v1/tasks/{task_id}/retry-node`：`node_file` 必须属于该任务 `step_files`，否则 **HTTP 400**（不再假成功）

### 6. 节点元数据

- `GET /api/v1/nodes`
- `GET /api/v1/nodes/{node_id}`

### 7. 健康探针

| 路径 | 含义 |
|------|------|
| `GET /health` | 存活；缺 LLM 仍可为 healthy |
| `GET /ready` | **进程就绪**（DB+配置）；LLM 在 `capabilities`，不挡 200 |

## 运行模式

| mode | 说明 |
|------|------|
| `auto` | 跳过人工审核节点（`mode_override` / `skip_review`）；Gate 可通过后直达发布 |
| `supervised` | BID/正文必审；Gate 按 RK 条件审 |
| `manual` | 逐步确认；检查失败可人工 `retry`/`approve`/`reject` |

路由细节见 `blog_writer/registry.json` 的 `routing` 与 `mode_config`。

## Webhook

启动任务时传 `callbackUrl`（可选 `callbackSecret`）。事件包括：

- `task.created` / `task.completed` / `task.failed` / `task.cancelled` / `task.paused` / `task.resumed`
- **`task.waiting_review`**（进入人工审核，平台可据此推送审核页）

签名（有 secret 时）：HMAC-SHA256，内容为  
`{event}.{task_id}.{timestamp}.{canonical_json(data)}`  
（`data` 使用 `sort_keys` + 紧凑分隔符），请求头 `X-Webhook-Signature`。

失败自动重试最多 3 次。管理接口 `/api/v1/webhooks*` **需鉴权**。

安全约束：

- `callbackUrl` 拒绝私网/localhost/链路本地等（防 SSRF）；发送时禁用 HTTP 跳转  
- 非 `admin`/`service` 用户仅能查看/操作**自己任务**的 Webhook  
- 自定义 `taskId` 若已存在返回 **409**（不会先覆盖他人 callback）

启用 Redis 后，Webhook 注册可跨进程恢复（TTL 约 7 天）；仍建议在任务结束后调用注销接口。

## 任务归属与权限

| 身份 | 可见/可操作范围 |
|------|----------------|
| 本地 JWT / `role=admin` / `role=service` | 全部任务 |
| SSO 等 `role=user` | 仅 `owner_id` 为自己的任务 |

- 创建任务时写入 `owner_id`（持久化在 `extra.owner_id`）  
- 普通用户**不可**自定义 `stepFiles`（防跳过门禁）；管理员可传 registry 子集（保持 registry 顺序）  
- `resume-from` / `rerun-from` **忽略请求体 mode**，始终使用任务已保存的 mode（防降级绕过审核）  
- 无归属的历史任务：仅特权角色可访问

## 发布与 WordPress（S010 / S011）

| 步骤 | 脚本 | 产物 |
|------|------|------|
| S010 | `tools/blog-writer/assemble_publish.py` | `007 发布包.md` + `007 发布包.json` |
| S011 | `tools/blog-writer/publish_to_wp.py` | `发布记录.json`（草稿） |

品牌目录需提供 `wp-config.json`（或 `config/wp-config.json`）：

```json
{
  "site_url": "https://cms.example.com",
  "username": "editor",
  "app_password": "xxxx xxxx xxxx xxxx"
}
```

无凭据时**自动 dry-run**（模拟发布），仍写入 `发布记录.json`（post_id=1, dry_run=true），不阻塞流程。配置 wp-config.json 后真正发布为草稿。

## 配置要点

### 配置文件索引

| 文件 | 用途 | 优先级 |
|------|------|--------|
| `.env` | 环境变量（LLM密钥、数据库、密码等） | 最高 |
| `blog_writer/config.json` | 应用配置（模型、工作流、安全） | 中 |
| `brands/<brand_id>/wp-config.json` | WordPress发布配置 | - |
| `blog_writer/registry.json` | 工作流步骤定义 | - |

详细配置见 [配置指南](CONFIGURATION.md)。

### 核心配置项

| 项 | 说明 |
|----|------|
| `BLOG_WRITER_CONFIG` | 配置文件绝对路径；默认 `blog_writer/config.json` |
| `LLM_API_KEY` / `LLM_BASE_URL` | 模型调用（必填） |
| `BLOG_WRITER_ADMIN_PASSWORD` | 管理员密码（必填） |
| `BLOG_WRITER_OPERATOR_PASSWORD` | 运营用户密码（可选，留空用管理员密码） |
| `BLOG_WRITER_API_TOKEN` | 平台服务 Token |
| `DB_BACKEND` | sqlite（默认）/ postgres / mysql |
| `MYSQL_HOST/PORT/DATABASE/USER/PASSWORD` | MySQL配置（DB_BACKEND=mysql时） |
| `REDIS_URL` | 可选；如 `redis://localhost:6379/0` |
| `BLOG_WRITER_STATE_BACKEND` | `memory`（默认）或 `redis` |
| `CORS_ORIGINS` | 跨域域名，逗号分隔 |
| `RESPONSE_CASE` | `snake`（默认）或 `camel`（Java对接用） |
| `workflow.default_mode` | `auto` / `supervised` / `manual`（默认auto） |
| `workflow.step_timeout_minutes` | 单步超时（默认30分钟） |
| `security.sso.*` | SSO单点登录配置（enabled=false默认关闭） |

- 配置项若声明对应 `*_env`（如 `admin_password_env`），**环境变量非空时始终覆盖配置文件**。
- 进程内共用一个 `ConfigManager`（`service_manager.get_config()`）；API `update`/`set` 在**锁外**触发回调：限流重建、Auth 缓存刷新、LLM 提供商清空、`use_file_fallback` 等运行时开关。
- **改库连接 / CORS origins / nodes·instance 根路径后请重启进程**。
- 任务终态后进程内完整状态会延迟清理，查询仍可走 DB / `_task_cache`；长期运行勿依赖内存字典为真相源。
- API JSON 统一包装对 **>1MB** / SSE / jsonl / 附件响应透传，避免缓冲破坏流式。
- 请求链路：`rate_limit → security → unified_response`；探针 `/health` `/ready` 不记访问日志且不限流。
- 限流判定顺序：**客户端 → 端点 → 全局**（避免被拒客户端耗尽全局部额度）。
- Agent `run_python` / `pure_code` 经 `agent/sandbox.py`：AST 拒 dunder/`os` 等导入、`-I`、cwd=`instance_dir`；**不是**绝对安全边界，多租户仍需容器隔离。
- 已移除无效配置项 `workflow.state_persistence`；勿再依赖该字段。

完整 OpenAPI：`/docs` 或 `docs/openapi.json`。

## 联调清单

1. 配置 `.env`：`LLM_API_KEY`、`LLM_BASE_URL`、`BLOG_WRITER_ADMIN_PASSWORD`（3个必填）
2. 单 worker 启动：`python run.py` 或 Docker Compose
3. 上传品牌资料：`POST /api/v1/brands/upload`（或前端上传）
4. 启动任务：`POST /api/v1/tasks/start`（免登录，传 brandPath + keywords + mode）
5. 轮询 `GET /api/v1/tasks/{id}`；supervised 时调 review；注意 `failed` 终态
6. （可选）配置 callbackUrl 接收终态与 `waiting_review`
7. 若跑到 S011：准备 `brands/<brand_id>/wp-config.json`，或接受 dry-run 模拟发布

## 已知边界（平台侧注意）

- 开启 Redis 后 Token/Webhook/**审核决策**可外置；等待协程会轮询 StateStore/DB，降低跨进程死等。**进行中的 asyncio.Event 仍绑定执行该任务的 worker**；多副本推荐：审核 API 与编排同连 Redis，或依赖 DB 决策 + 无 waiter 时自动续跑  
- 节点可配置 `llm_model` / `resources.llm_model`，对应 `llm.models.<name>`  
- 单步超时可被节点 `resources.step_timeout_minutes` 覆盖；任务级 Token 上限见 `workflow.max_tokens_per_task`（默认 0=不限制）  
- 错误同时看 HTTP status 与 body.`code`  
- 节点 check 的 `::exec:` **仅允许** `python -c` / `python3 -c`（已禁用任意 shell）  
- Agent 工具 `run_python` / pure_code：禁止 `os`/`sys` 与 dunder 属性逃逸，`open` 限制在任务 `instance_dir`；另有 AST 预检  
- `retry-node` 传入不在任务步骤中的文件名会失败（400），不会标记假成功  
- SSO：`userinfo` 失败时**拒绝登录**（不再使用 `unknown` 身份，避免归属串号）  
- SSO 启用后默认**不可**用本地 password-only 登录；需显式 `security.sso.allow_local_fallback=true`  
- 热启用 SSO（或关闭本地降级）会吊销全部本地 JWT  
- 改密成功后本地 JWT 全部吊销，需重新登录  
- 同一任务重复提交不同审核决策会被拒绝（相同决策幂等）  
- 旧文档中的 Flask / `WorkflowEngine` / `/api/v1/workflow/*` **已废弃**  
- 详细变更列表：[变更说明-2026-08-04](变更说明-2026-08-04.md)（含第十四～十七节审查落地）
