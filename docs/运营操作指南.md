## 快速开始

### 部署方式

项目支持两种部署方式，根据公司平台条件选择：

| 方式 | 适用场景 | 需要安装 |
|------|---------|---------|
| **Docker 部署** | 公司平台支持 Docker/K8s | Docker Engine 24+、Docker Compose v2 |
| **原生部署** | 单机运行或开发调试 | Python 3.12+ |

### 方式一：Docker 部署（推荐）

```bash
# 1. 克隆代码
git clone <repo-url> && cd blog-writer-main

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env，设置 BLOG_WRITER_ADMIN_PASSWORD、LLM_API_KEY、DB_PASSWORD 等

# 3. 准备配置文件
#    复制 config.json.example 为 config.json，按需修改

# 4. 一键启动全部服务
docker compose up -d

# 5. 查看服务状态
docker compose ps
```

启动后访问：
- **Web 界面**：`http://服务器IP:8000`
- **API 文档**：`http://服务器IP:8000/docs`

### 方式二：原生部署

```bash
# 1. 创建虚拟环境
python -m venv .venv
.venv\Scripts\activate          # Windows

# 2. 安装依赖
pip install -r requirements.txt

# 3. 配置环境变量
cp .env.example .env
# Windows PowerShell:
#   $env:BLOG_WRITER_ADMIN_PASSWORD = "your-password"
#   $env:LLM_API_KEY = "your-key"

# 4. 启动
python run.py
```

> 原生部署默认使用 SQLite，无需额外数据库。生产环境建议安装 PostgreSQL + Redis。

### 浏览器访问

启动后打开浏览器访问：
- **Web 管理界面**：`http://127.0.0.1:8000`（含任务管理、节点管理、配置管理）
- **API 交互文档**：`http://127.0.0.1:8000/docs`（Swagger UI，可在线调试）
- **运行状态**：`http://127.0.0.1:8000/health`（健康探针）

### 你只需要准备两样东西

1. **品牌资料**（.md/.txt 文件，通过前端上传）
2. **要写的关键词**

### 品牌资料上传

**方式一：前端上传（推荐）**
1. 首页「选择品牌」下拉框旁点击「+ 上传新品牌」
2. 输入品牌中文显示名（如「SMS Boosting」）
3. 选择文件（支持多选，或直接选文件夹）
4. 仅支持 .md / .txt，单文件 ≤ 10MB
5. 上传成功后自动出现在下拉框，可直接选中启动任务

**方式二：手动放置**
在 `brands/` 目录下新建品牌文件夹，放入 .md 文件：
```
brands/sms-boosting/
├── 品牌知识库.md      ← 公司介绍、产品信息
├── 语气调性指南.md    ← 文章的语气和风格
└── 禁用词清单.md      ← 不能出现的词汇
```

> 中文品牌名会自动转拼音生成目录名（如「短信平台」→ `duan-xin-ping-tai`）。

## Web 界面操作

### 登录（可选）

**2026-08-12 更新**：品牌管理和任务操作**无需登录**，打开页面即可使用。只有「节点管理」和「系统配置」需要管理员登录。

如需使用管理功能：
1. 点击左侧边栏「管理员登录」
2. 输入管理员密码（默认 `admin123`，生产环境请修改）
3. 登录成功后可使用节点管理、系统配置

### 任务管理

- **创建任务**：
  1. 「选择品牌」下拉框选择品牌（或点「+ 上传新品牌」上传）
  2. 填写关键词
  3. 选择运行模式（推荐 `auto` 全自动，或 `supervised` 监督模式）
  4. 可选：填写附加要求、禁用词白名单、温度系数
  5. 点击「启动任务」
- **查看任务**：任务列表显示所有任务的状态、进度
- **操作任务**：点击任务可查看详情、日志，支持暂停、恢复、取消
- **断点续跑**：任务失败/取消后，可通过 API 从指定步骤继续（见「任务控制」章节）

### 节点管理（需登录）

管理员可在 Web 界面中：
- 查看所有工作流节点定义（18个节点）
- 编辑节点 JSON（提示词、检查规则等）
- 校验节点配置
- 新建/删除节点

### 配置管理（需登录）

Web 界面支持在线修改：
- LLM 模型配置（API Key、模型名称、温度等，密钥不回显）
- 工作流参数（默认模式、超时、迭代次数等）
- Token 消耗统计

## API 操作（对接平台用）

> **2026-08-12 更新**：品牌接口和任务接口**免登录**，直接调用即可。管理员接口（节点CRUD、系统配置）需登录。

### 创建写作任务（免登录）

```bash
curl -X POST http://127.0.0.1:8000/api/v1/tasks/start \
  -H "Content-Type: application/json" \
  -d '{
    "brandPath": "./brands/sms-boosting",
    "keywords": "SMS API 对接",
    "mode": "auto",
    "userNote": "面向技术人员，重点讲API易用性"
  }'
```

> 字段名支持 camelCase（如 `brandPath`）和 snake_case（如 `brand_path`）两种格式。

### 上传品牌资料（免登录）

```bash
curl -X POST http://127.0.0.1:8000/api/v1/brands/upload \
  -F "display_name=SMS Boosting" \
  -F "files=@品牌知识库.md" \
  -F "files=@语气调性指南.md"
```

### 查询任务状态（免登录）

```bash
curl http://127.0.0.1:8000/api/v1/tasks/{task_id}
```

终态包括：`completed`（完成）、`failed`（失败）、`cancelled`（取消）、`rejected`（驳回）。

### 查看任务日志（免登录）

```bash
curl http://127.0.0.1:8000/api/v1/tasks/{task_id}/logs
```

### 管理员登录（管理接口用）

```bash
curl -X POST http://127.0.0.1:8000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"password": "admin123"}'
```

返回：
```json
{
  "code": 0,
  "data": {
    "token": "xxx...",
    "role": "admin",
    "expires_in": 86400
  }
}
```

## 单次写作

### 通过 Web 界面

1. 打开 Web 管理界面（无需登录）
2. 「选择品牌」下拉框选择品牌（没有就点「+ 上传新品牌」）
3. 填写关键词
4. 选择运行模式（推荐 `auto` 全自动）
5. 可选：填写附加要求、禁用词白名单
6. 点击「启动任务」，等待完成

### 通过 API

```bash
curl -X POST http://127.0.0.1:8000/api/v1/tasks/start \
  -H "Content-Type: application/json" \
  -d '{"brandPath":"./brands/sms-boosting","keywords":"SMS API对接","mode":"auto"}'
```

运行完成后，结果在 `blog_writer/instance/<task_id>/` 目录下，包含：
- `004 正文.md` — 文章正文
- `006 呈现文档.html` — 带样式的HTML
- `007 发布包.md` / `.json` — 发布包
- `发布记录.json` — WordPress发布记录（如有）

## 人工审核

### 三种运行模式

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| `auto` | 全自动，无人干预 | 低风险内容，批量生产 |
| `supervised` | 关键节点审核 | 日常使用，推荐模式 |
| `manual` | 每步都确认 | 高风险内容，敏感话题 |

### Web 界面审核

当任务进入等待审核状态时：
1. 在 Web 界面任务列表中找到「待审核」标签的任务
2. 点击进入任务详情
3. 查看当前节点的产出内容
4. 选择操作：**通过** / **驳回** / **修改后通过** / **重试**

### API 审核

```bash
curl -X POST http://127.0.0.1:8000/api/v1/tasks/{task_id}/review \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{"decision": "approve", "modifications": {}}'
```

`decision` 可选值：

| 值 | 含义 |
|------|------|
| `approve` | 通过，继续执行 |
| `reject` | 驳回，退回上一步重新生成 |
| `modify` | 修改后通过（需传 `modifications`） |
| `retry` | 重跑当前审核相关步骤 |

### 命令行审核

使用 `supervised` 或 `manual` 模式时，命令行会暂停等待操作：

```
🔔 请人工审核：BID识别结果

识别的关键词：SMS API对接
识别的受众：技术人员
识别的语气：专业技术

请选择操作：
1. ✅ 通过，继续
2. ✏️ 修改后继续
3. 🔄 重新生成
4. ❌ 终止任务
```

## 任务控制

### 支持的操作

| 操作 | 说明 | Web 界面 | API（免登录） |
|------|------|---------|--------------|
| 暂停 | 暂停正在运行的任务 | ✅ | `POST /tasks/{id}/pause` |
| 恢复 | 恢复暂停的任务 | ✅ | `POST /tasks/{id}/resume` |
| 取消 | 取消任务（停止运行） | ✅ | `POST /tasks/{id}/cancel` |
| 断点续跑 | 从当前步骤继续（失败/取消后） | ❌ | `POST /tasks/{id}/resume-from` |
| 指定重跑 | 从指定步骤重新开始 | ❌ | `POST /tasks/{id}/rerun-from` |
| 重试节点 | 重试指定步骤 | ❌ | `POST /tasks/{id}/retry-node` |

### 断点续跑（2026-08-12 已修复）

任务失败或取消后，不需要从头重启，可以从断点继续：

```bash
# 从当前失败步骤继续
curl -X POST http://127.0.0.1:8000/api/v1/tasks/{task_id}/resume-from

# 从指定步骤重新开始（如从S007视觉素材步骤重跑）
curl -X POST http://127.0.0.1:8000/api/v1/tasks/{task_id}/rerun-from \
  -H "Content-Type: application/json" \
  -d '{"nodeFile": "S007-visual.json"}'
```

支持的状态：`failed` / `cancelled` / `paused` 均可续跑。

### 重试失败节点

```bash
curl -X POST http://127.0.0.1:8000/api/v1/tasks/{task_id}/retry-node \
  -H "Content-Type: application/json" \
  -d '{"nodeFile": "S003-structure.json"}'
```

> `nodeFile` 必须是该任务 `step_files` 中的文件名，否则会返回错误。

### 查看待审核列表

```bash
curl http://127.0.0.1:8000/api/v1/tasks/reviews/pending
```

## 常见问题

### Q1：关键词写错了怎么办？

**答**：直接修改配置文件里的 `keywords` 字段，重新运行即可。如果任务已开始，可先取消再重新创建。

### Q2：文章风格不对？

**答**：两个方法：
1. 修改品牌文件夹里的 `语气调性指南.md`
2. 在 `user_note` 里加具体要求，比如"更活泼一些"

### Q3：运行很慢？

**答**：检查 `mode` 设置：
- `auto` 模式最快，跳过人工审核
- `supervised` 会暂停等待审核，需要人工操作
- `manual` 最慢（每步确认）

### Q4：如何查看任务日志？

**答**：
- **Web 界面**：任务详情页可直接查看日志
- **API**：`GET /api/v1/tasks/{task_id}/logs`
- **文件系统**：`instance/<任务目录>/` 下的日志文件

### Q5：任务失败了怎么办？

**答**：不需要从头重启，使用**断点续跑**：

```bash
curl -X POST http://127.0.0.1:8000/api/v1/tasks/{task_id}/resume-from
```

系统会从失败的步骤继续执行，已完成的步骤不会重跑。如果是某个节点的问题，也可以指定步骤重跑：

```bash
curl -X POST http://127.0.0.1:8000/api/v1/tasks/{task_id}/rerun-from \
  -H "Content-Type: application/json" \
  -d '{"nodeFile": "S007-visual.json"}'
```

### Q6：修改 .env 后不生效？

**答**：必须**重启服务**。uvicorn --reload 只监听代码文件变化，不会重新加载环境变量。需要杀掉所有 Python 进程后重新启动。

### Q7：WordPress 发布失败？

**答**：检查品牌目录下是否有 `wp-config.json`，包含 `site_url`、`username`、`app_password` 三个字段。注意 `app_password` 是 WordPress 后台生成的应用密码，不是登录密码。

未配置时系统会自动 dry-run（模拟发布），不阻塞流程。

### Q8：如何进行健康检查？

**答**：
- 存活检查：`GET /health`
- 就绪检查：`GET /ready`（返回 200 表示服务就绪）
- 探针不消耗限流配额，适合监控系统定时调用

## 配置字段说明

### 任务配置（JSON）

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| `brand_path` | ✅ | 字符串 | 品牌文件夹路径，相对于 `brands/` 目录 |
| `keywords` | ✅ | 字符串 | 写作关键词，最长500字符 |
| `mode` | ❌ | 字符串 | `auto` / `supervised` / `manual`，默认 `auto` |
| `user_note` | ❌ | 字符串 | 附加要求，如"面向技术人员"，最长2000字符 |
| `brand_site_url` | ❌ | 字符串 | 品牌官网URL |
| `callback_url` | ❌ | 字符串 | 回调通知地址（平台对接用） |
| `callback_secret` | ❌ | 字符串 | 回调签名密钥（HMAC-SHA256） |
| `task_id` | ❌ | 字符串 | 自定义任务ID（不传则自动生成） |
| `step_files` | ❌ | 数组 | 自定义步骤列表（仅管理员可用） |
| `forbidden_whitelist` | ❌ | 数组/字符串 | 本任务禁用词豁免白名单 |

### 环境变量

| 变量 | 必填 | 说明 |
|------|------|------|
| `BLOG_WRITER_ADMIN_PASSWORD` | ✅ 生产 | 管理员密码 |
| `LLM_API_KEY` | ✅ | AI 模型 API Key |
| `LLM_BASE_URL` | ❌ | API 地址，默认 `https://api.deepseek.com/v1` |
| `REDIS_URL` | ❌ | Redis 连接地址，用于状态外置 |
| `BLOG_WRITER_MODE` | ❌ | `development` / `production` |

## 最佳实践

### 1. 从小批量开始

```json
{
  "tasks": [
    {"keywords": "第一个关键词"},
    {"keywords": "第二个关键词"}
  ]
}
```

### 2. 用 supervised 模式试运行

- 先跑1-2篇看看效果
- 确认风格和质量后再批量生产
- 在 Web 界面中实时查看审核状态

### 3. 记录有效的配置

- 把效果好的配置保存为模板
- 下次直接复用，不用从零开始
- Web 界面可查看历史任务配置

### 4. 善用 user_note

- 不要只写关键词，加上具体要求
- 比如"写5000字"、"包含3个案例"、"面向CFO"
- 附加要求越具体，输出质量越高

### 5. 关注 Webhook 回调

如果对接了公司平台，任务状态变更时会自动回调通知。支持的事件：
- `task.created` / `task.completed` / `task.failed`
- `task.cancelled` / `task.paused` / `task.resumed`
- `task.waiting_review`（进入审核，平台可据此推送审核通知）

## 发布到 WordPress（可选）

若流水线跑到「发布」步骤，需要在品牌目录准备 `wp-config.json`：

```json
{
  "site_url": "https://cms.example.com",
  "username": "editor",
  "app_password": "xxxx xxxx xxxx xxxx"
}
```

文件位置：`brands/<品牌ID>/wp-config.json`（模板见 `brands/wp-config.example.json`）

**没有该文件时**：系统自动 dry-run（模拟发布），生成 `发布记录.json`（post_id=1, dry_run=true），任务正常完成，不会失败。

**配置后**：真正发布到 WordPress，文章状态为 draft（草稿），需在 WP 后台手动发布。

获取应用密码：WP后台 → 用户 → 个人资料 → 应用密码 → 添加新应用密码 → 复制（只显示一次）。
